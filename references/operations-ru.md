# Русская операционная инструкция

Это отдельный навык для Codex и Claude Code: изображения → Hunyuan → исправление модели и запекание в Blender → текстурирование в Modddif → материалы, скелет, анимация и проверка экспорта. Навык не является самостоятельной программой, которая сама получает доступ к Chrome. Браузерные действия выполняет агент через реально подключённые инструменты управления компьютером; локальные операции выполняются через Blender в фоновом режиме.

Подробные технические форматы находятся в `commands.md`; имена файлов, команд и JSON-полей не переводятся. Источники перечислены в `sources.md`. Английские инструкции и этот документ описывают одну процедуру, а не две разные версии.

## Установка и запуск

Распакуйте архив и откройте PowerShell в каталоге, где находится `install.mjs`.

```powershell
# NEW: установка навыка в выбранный проект для обоих агентов.
node .\install.mjs --project "C:\Projects\CharacterStudio" --target both
```

Для Codex будет создан `.agents\skills\character-pipeline`, для Claude Code — `.claude\skills\character-pipeline`. Установщик не изменяет настройки MCP, профиль Chrome, `AGENTS.md` или `CLAUDE.md`. Он не перезаписывает существующий навык. Запускайте агента из выбранного проекта. В Codex вызовите `$character-pipeline`, в Claude Code — `/character-pipeline`.

Пример задания:

```text
Используй character-pipeline. Hunyuan и Modddif уже открыты в моём Chrome.
Референсы находятся в C:\Projects\CharacterStudio\references.
Создай рабочий каталог C:\Projects\CharacterStudio\work\character-01.
Сохрани пропорции, все части тела, одежду и аксессуары.
Работай с Blender в фоновом режиме. Нужны модель с текстурами,
проверенный скелет, idle и walk, .blend, GLB и проверочные рендеры.
Сначала проверь подключение к нужным вкладкам и установленный Blender.
Не публикуй проект и не покупай кредиты. Перед генерациями согласуй лимит.
Если какая-то часть результата не проверена, укажи это явно.
```

## 1. Предварительная проверка

Прочитайте уже известные требования пользователя и файлы проекта. Не задавайте повторно вопросы, ответы на которые уже есть. Определите исходные изображения, целевую программу, требуемую анимацию, необходимость мимики, расположение Blender, рабочий каталог и разрешённые сервисы.

Открытые вкладки сами по себе не означают, что агент ими управляет. Проверьте доступ именно к нужным Hunyuan и Modddif, снимок экрана, загрузку файлов, скачивание и управление мышью. Для рисования масок необходимо движение указателя с зажатой кнопкой, а не только нажатие кнопок DOM. Если такого инструмента нет, остановите соответствующий этап с `BLOCKED_POINTER_CAPABILITY`, а не имитируйте успешное рисование.

Для Claude Code используйте разрешённое подключение Claude in Chrome. Для Codex подойдёт уже настроенный computer use либо отдельно разрешённое подключение Chrome DevTools MCP к существующей сессии. Подробности и официальные ссылки находятся в `setup-and-browser.md`. Не копируйте cookies, не открывайте удалённую отладку в публичную сеть и не перезапускайте основной профиль пользователя с опасными флагами.

Выполните `doctor`, локальные тесты и Blender selftest. В среде, где был создан этот архив, Blender и реальные браузерные проекты не запускались. Поэтому локальный selftest обязателен. Успех синтетического теста всё равно не доказывает качество конкретного персонажа.

## 2. Рабочий каталог и разрешения

Создайте отдельный каталог через `pipeline.mjs init`. Оригиналы не изменяйте. Сохраняйте новые версии в `inputs/` и результаты отдельных запусков в `runs/`. Файл `state.json` содержит журнал, а `NEXT_ACTION.md` — состояние для продолжения работы.

Начальный бюджет генераций равен нулю намеренно. Получите разрешение на число генераций и максимальный расход, запишите разрешённые домены и доказательство согласия. Не считайте наличие подписки разрешением покупать дополнительные кредиты. Отдельно согласуйте публикацию, использование нового сервиса, например Mixamo, и загрузку конфиденциальных материалов.

Файлы approval — записи о реальном решении, а не способ его придумать. Они должны содержать имя проверяющего, основание, область разрешения и SHA-256 конкретного входного файла. Если пользователь делегировал визуальную проверку агенту, укажите именно агента и сохраните открытые им рендеры. Не пишите «одобрено пользователем», если пользователь этого не делал.

## 3. Референсы

Проверьте согласованность вида спереди, сбоку и сзади, а также отдельного лица. Совпадать должны рост, форма головы, пропорции, одежда, волосы, расположение аксессуаров и выражение лица. Разделяйте ракурсы на отдельные файлы. Обзорный коллаж не обязательно является корректным входом для многовидовой генерации.

Поза должна позволять увидеть руки, ноги и необходимые пальцы. Не растягивайте толстого или низкого персонажа до стандартных человеческих пропорций. Для вымышленных существ заранее запишите обязательные признаки: например, два крыла, хвост, длинные уши и конкретное число пальцев. Затем проверяйте их после каждого изменения модели.

Если отсутствующий ракурс нужно генерировать, используйте только действительно доступный инструмент и получите согласованный вариант. Отмечайте дорисованные детали как предположения. Не выдавайте сгенерированный вид сзади за фотографически подтверждённую геометрию.

## 4. Hunyuan

В нужной вкладке сначала изучите текущий интерфейс: режим генерации по изображениям, доступные ракурсы, настройки геометрии, ретопологии, UV и экспорта. Не предполагайте, что число бесплатных генераций или расположение кнопок совпадает с роликом. Не используйте выдуманные API или скрытые запросы с извлечёнными токенами.

Загрузите изображения в правильные роли. Проверьте миниатюры, особенно стороны left/right и front/back. Перед отправкой зафиксируйте стоимость и параметры, зарезервируйте бюджет локальной командой, отправьте запрос один раз и запишите идентификатор задания. При тайм-ауте проверяйте исходное задание, а не запускайте новое вслепую.

Скачайте подробную исходную модель и отдельную облегчённую версию. Проверьте оба файла в Blender. Сначала оценивайте силуэт и строение, затем текстуру. Слипшиеся пальцы, отсутствующее крыло, неправильный профиль лица и соединённые ноги нельзя исправить одним красивым материалом.

Результат автоматической ретопологии — кандидат. Четырёхугольники сами по себе не означают, что модель хорошо сгибается. Если форма принципиально неверна, исправьте её или получите другой источник до затрат на финальное текстурирование.

## 5. Исправление геометрии в Blender

Начните с `inspect` и одинаковых ортографических рендеров. Зафиксируйте количество объектов и полигонов, трансформации, материалы, UV, открытые границы, проблемные рёбра и отдельные компоненты. Не удаляйте мелкие компоненты автоматически: это могут быть зубы, глаза, пуговицы или детали причёски.

При нормализации low и high должны получить одну и ту же трансформацию. Нельзя независимо подгонять их габариты: после этого запекание может перестать соответствовать поверхности. Сохраняйте пропорции. После создания скелета не применяйте глобальные операции над топологией без возврата к версии до риггинга.

Встроенный `prepare` выполняет ограниченную очистку: удаляет изолированные вершины, при явно выбранном малом допуске объединяет близкие вершины и пересчитывает нормали. Он не является универсальным исправлением анатомии, отверстий, самопересечений и всех дефектов сетки. Такие изменения агент должен делать отдельной проверяемой операцией на конкретном участке.

Не закрывайте автоматически отверстия рукавов, рта, глазниц и подола. Не объединяйте все слои одежды в одну оболочку. Для пальцев, коленей, локтей и плеч проверяйте направление рёбер и место сгиба. Для мимики необходима специально подготовленная топология губ и век.

`retopo` создаёт пробный QuadriFlow-результат. После него заново рассматриваются UV, нормали, текстуры и веса. Симметрия включается только тогда, когда она соответствует персонажу; асимметричные волосы и аксессуары не должны исчезнуть.

## 6. UV и запекание

Сохраняйте пригодную развёртку. Для новой развёртки нужно отдельное согласование, потому что изменится соответствие текстур поверхности. Проверяйте наложения, растяжение, плотность, швы и промежутки между островами. Встроенная проверка UV не доказывает отсутствие всех наложений и хорошую художественную раскладку.

До финального запекания зафиксируйте топологию, UV, триангуляцию и нормали сглаживания. Тангенциальная normal map зависит от всех этих данных. Совпадение количества вершин не доказывает совместимость карты после экспорта из веб-сервиса.

Указывайте конкретные пары low/high. Изолируйте посторонние поверхности, чтобы луч с ноги не попадал в другую ногу или одежду. Начинайте с небольшой дистанции относительно масштаба детали, а не копируйте большое значение из видео. При необходимости используйте проверенный cage с той же топологией.

Помощник создаёт normal/AO и отдельную диагностическую карту попаданий. Проверяйте не только её числовой показатель, но и лицо, пальцы, уши, швы и тонкие детали. Хорошая статистика не исключает попадание луча в неправильную поверхность. Сначала отладьте процесс на небольшом разрешении, затем запеките окончательный вариант.

Для отправки исправленной модели в Modddif используйте `handoff`: это промежуточный GLB до риггинга, а не финальный релиз. Он не даёт разрешения на загрузку или публикацию — эти действия проверяются отдельно.

## 7. Modddif: лицо, материалы и локальные исправления

Перед созданием проекта проверьте режим приватности. Не повторяйте автоматически публичный вариант из ролика. После импорта убедитесь, что сервис не изменил геометрию и UV; при изменении нужно принять новую версию и пересмотреть запекание либо вернуться к исходной сетке. [M1, M10]

Важно: множество загруженных референсов не означает совместное использование всех изображений. Проверяйте реально активный референс для текущего действия. Инструменты генерации участка и переноса исправления различаются; подробная карта возможностей находится в `modddif.md`. [M2–M3]

Рекомендуемый порядок: лицо, шея и уши, передняя часть тела, бока, спина, кисти и стопы, скрытые участки. Начните с лица, потому что неправильно сформированную идентичность дорого исправлять после полной работы над телом. Сравнивайте положение глаз и рта с геометрией, а не только красоту двумерного результата.

Для дефекта сначала определите причину: цвет, шов проекции, нарисованная тень, непрокрашенная поверхность или реальная неправильная форма. Зафиксируйте вид до изменения и второй контрольный ракурс. Выделяйте минимально достаточную область, проверяйте видимую маску, оценивайте новый результат и применяйте исправление обратимым способом. После этого смотрите на модель со второго ракурса.

Если исправление не проявилось, сначала проверьте активный инструмент, слой, объект и видимость. Не тратьте ещё одну генерацию только потому, что первый мазок не попал в нужный слой. Если меняется уже принятое лицо ради исправления сапога, уменьшите область или смените подход.

Два безрезультатных локальных прохода — повод изменить причину, а не повторять тот же запрос. Используйте другой ракурс, исправьте геометрию, измените область либо выполните контролируемую локальную правку текстуры. Перед экспортом верните скрытые детали и проверьте все стороны.

## 8. Материалы после возвращения в Blender

Сопоставляйте материалы и текстуры по их реальному назначению. Base color — цветовые данные; normal, roughness, metallic и AO — данные, которые не должны получать обычную цветовую коррекцию. Не связывайте один материал со всеми объектами ради устранения розового цвета: сначала проверьте потерянные файлы и узлы.

Кожа и обычная ткань не должны становиться металлическими ради выразительных бликов. Настраивайте кожу, волосы, ткань и металл отдельно. Не используйте одинаковые IOR и subsurface из ролика для всех поверхностей. Подповерхностное рассеяние зависит от масштаба и возможностей целевого движка. Проверяйте нейтральное освещение до финального художественного рендера.

Не смешивайте две normal map простым усреднением RGB. Не умножайте AO в base color повторно, если он уже запечён. После изменения UV или нормалей сглаживания убедитесь, что используемая карта всё ещё корректна.

## 9. Скелет и веса

Если модель уже имеет хороший скелет, сначала проверьте его. Для обычного гуманоида можно использовать Mixamo только после отдельного разрешения на загрузку. Для локального пути подготовьте скелет по реальным суставам модели. Rigify генерирует управляющий риг после правильной установки metarig, а не определяет анатомию вместо этой работы.

Получите фронтальный и боковой рендер с известными камерами. Определите центры суставов в нескольких ракурсах, создайте кандидат JSON и визуализацию костей поверх модели. Подтвердите глубину плеча, положение таза, плоскости сгибания локтей/коленей, запястья и пальцы. Пример синтетического скелета из архива нельзя выдавать за готовую человеческую анатомию.

`rig` создаёт простой деформирующий скелет, назначает автоматические веса и проверяет их. Отдельные жёсткие объекты можно явно привязать к конкретной кости. Непривязанные вершины вызывают ошибку: агент не должен автоматически прикреплять их к случайной ближайшей кости.

Проверьте подъём рук, сгибание локтей и коленей, приседание, поворот предплечий, движение кистей и головы. Для крыльев и хвоста нужны свои кости и тестовые позы. При дефекте выясните, виноваты ли положение сустава, топология или веса. Хорошая сумма весов не доказывает правильную деформацию.

## 10. Анимация

Для простого проверочного результата используйте явные ключи поз. Для ходьбы нужна полноценная анимация: разрешённый источник движения или осмысленно созданный цикл. Двух ключей сгибания недостаточно, чтобы объявить естественную походку.

При ретаргетинге согласуйте исходную позу, оси, названия костей, масштаб и FPS. Начните с короткого теста. Встроенный `retarget` переносит вращения и согласованное перемещение, но не выполняет автоматически фиксацию стоп, распределение twist, извлечение root yaw или лицевую мимику.

Проверяйте скольжение стоп, высоту над землёй, направление коленей, пересечения рук и одежды. Выберите in-place или движение корня и не удваивайте перенос одновременно на тазе и root. Для исправления контакта используйте проверенную IK-операцию, затем запеките результат на деформирующие кости и повторите тест.

Замкнутый цикл должен совпадать не только по первой и последней позе, но и по характеру скорости и фазе шага. Запишите FPS, длительность, политику конечного дублирующего кадра и root motion. Сохраняйте каждый принятый action отдельно. Несколько анимаций в одном GLB требуют намеренной сборки NLA/actions и проверки списка экспортированных клипов.

Мимика — отдельный этап. Нарисованный закрытый рот и нарисованные глаза не становятся полноценным лицевым ригом после автоматического риггинга тела. Для речи нужны подходящая топология, формы/кости и проверка экспорта морфов. Не обещайте это, если выполнено только движение челюсти.

## 11. Проверка, экспорт и честный результат

Выполните `qa` для конкретного итогового `.blend`. После успешной механической проверки используйте `export_candidate`, чтобы получить файл для проверки в целевой программе. Затем проведите реальные визуальные и playback-тесты. Только после этого оформляйте release approval и выполняйте `export`.

Эта последовательность важна: нельзя объявить совместимость с движком до получения и просмотра экспортированного кандидата. Помощник проверяет повторный импорт GLB в Blender, но не подменяет проверку в игре, веб-просмотрщике или другом движке. FBX нужно проверять отдельно.

Передавайте реальные `.blend`, GLB, при необходимости FBX, текстуры, перечень клипов, рендеры, отчёты, сведения об источниках и ограничения. `VERIFIED_FOR_TARGET` допускается только после всех необходимых проверок. Иначе используйте `CANDIDATE`, `BLOCKED` или `INCOMPLETE` с конкретным объяснением.

При прерывании работы сохраните `NEXT_ACTION.md`: принятая версия и хеш, стадия, идентификатор задания в браузере, оставшийся бюджет, непроверенный дефект и следующее безопасное действие. Не обещайте продолжить работу в фоне после окончания сессии.
