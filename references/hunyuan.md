# Hunyuan: screenshot-driven geometry generation

The user's intended service is `https://3d.hunyuan.tencent.com/`. Its authenticated UI was not executed while this package was authored. Treat the provided tutorial as a route suggestion, not a selector map or an entitlement guarantee. The official Hunyuan3D Studio paper discusses a modular asset pipeline; it does not prove every module is exposed to every web account. The open-source Hunyuan3D repository and Tencent cloud API are different interfaces with their own versions and licenses. [H1–H3]

## Observe and map

Select the authorized tab and verify the exact origin. Inspect the current project list and any unsaved work. Record language, account-visible permissions, generation model label, image-to-3D modes, accepted reference counts, topology/UV/export controls and visible prices. Mark unavailable capabilities as unavailable. Do not click subscription upgrades, “publish,” deletion or trial enrollment to make a desired feature appear.

A likely conceptual route is studio → image-conditioned geometry → multiple views → generate → topology → UV → export. Translate this into actions only from controls visible now. If the service supports only one reference in the available mode, choose the agreed primary view and disclose the limitation; do not paste a contact sheet and claim true multiview conditioning.

## Input contract

Choose image generation mode, not text-only mode, when the task is to preserve supplied identity. Upload the verified views in the correct roles. Inspect each thumbnail after upload; front/back swaps are easy to miss. Establish whether “left” refers to the subject's left or the viewer's left. Record that convention with the inputs.

Match the accepted input pose and crop. Check that hair, feet, horns, wings and accessories fit within the image. Keep original aspect ratio unless a deliberate padded crop is required. Never stretch a short/fat character to a standard humanoid silhouette to satisfy a tool. For non-humanoids, body generation can continue even when later humanoid rigging is unsuitable.

Before generation, capture all selected inputs and settings. Reserve the actual observed cost, then submit once. Capture the new job identity immediately. Wait on the same job with bounded polling. If the UI disconnects, inspect history and the existing job before retrying. A generation may complete and consume credits after the first tab stops showing progress.

## Select geometry rather than a flattering thumbnail

Download a source candidate at the highest useful geometry fidelity available within the approved budget. Highest available is not automatically best: unusable file size or noisy geometry may make a lower setting preferable. Preserve the source untouched. Inspect in Blender with materials disabled as well as enabled.

Evaluate the reference silhouette in front, side, back and three-quarter views. Count important parts; look for fingers joined to thighs, hair merged into shoulders, closed armpits, folds welded across the legs, missing accessories and incomplete back surfaces. Compare face profile, eye placement and jaw depth. Use a defect table with severity and likely correction cost.

Approve one candidate or one focused regeneration. Do not regenerate a good body repeatedly merely because a texture is weak; texturing occurs later. Conversely, do not spend multiple texture generations trying to hide a geometry defect.

## Retopology and UV candidates

Keep high and low exports distinct. If a topology operation modifies the source in place, duplicate/checkpoint it first. Select a polygon target from the intended runtime budget and the character's deformation complexity. Document whether the UI counts triangles, quads, polygons or vertices. Never reinterpret a slider's units from the tutorial.

Inspect the low result: important shape retention, connected joint regions, face loops, hand separation, multiple objects and material boundaries. Hunyuan topology is a candidate, not an animation-readiness certificate. If a result pinches or loses anatomy, create another budgeted topology candidate or repair locally before unwrapping.

Preserve usable UVs; request UV generation only when needed. Confirm that a subsequent texture stage will use the same mesh and UVs. Download geometry-only and textured variants when useful and available, but do not rely on a filename alone to distinguish them.

## Optional segmentation or rigging controls

If visible segmentation helps separate clothes, hands, face or rigid accessories, duplicate the project first and verify the split surfaces and object names after export. Do not split every semantic region into a disconnected deformation seam.

If a rig or animation export is actually present, it may be tested as a candidate after the mesh is stable. Download and inspect hierarchy, rest pose, weights, actions and deform quality. Prefer a good existing rig over rerigging. Do not claim that the open-source geometry model itself implements an observed web rigging feature, and do not invent a hidden rigging API when the UI lacks one.

## Browser-to-local checkpoint

Write an event containing reference hashes, settings, observed cost, visible job ID, accepted result, project URL without sensitive tokens, export type, local filename/hash and review screenshots. Run `check-glb` and `inspect` on each GLB. Confirm high/low pairing by bounds and renders. Any unknown coordinate transform is resolved before baking, with a shared normalization transform for both meshes.
